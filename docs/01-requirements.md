# 01 · 需求（用户、目标、范围、成功标准）

## 用户与目标

- **用户**：小影内容运营人员。给定一个内容活动任务（主题 + 预算 + 截止时间），需要在预算与工期内产出一份可直接执行的活动方案（素材、脚本、成本估算）。
- **目标**：Agent 自主完成「检索素材 → 生成脚本 → 成本估算 → 保存方案」，在预算/工期不可行时能自动重规划（如降级制作档位），不可行时给出明确原因与缺口，而不是硬塞一个超支方案。

## 输入与输出

- **输入**：`theme`（主题）、`budget`（预算，模拟单位）、`deadline_hours`（截止工时，模拟）。
- **输出**：`result.json`（状态、任务计划、工具结果、费用/工期合计、未完成原因）；成功时额外保存 `plan.json`（完整方案）。

## 范围

- **做**：ReAct 决策循环、5 个业务工具（本地实现）、计费与步数约束、预算超限降级重规划、工具失败处理（重试/兜底/停止）、重复执行幂等与失败续跑、CLI 运行入口、pytest 测试、双模型接入（离线 Mock + OpenAI 兼容真实模型）。
- **不做**：Web 界面、线上部署、多 Agent 协作、生产级 Runtime、素材的真实抓取（合成数据）。

## 成功标准

1. 正常输入 → 产出保存的方案，总费用 ≤ 预算、总工期 ≤ 截止时间；
2. 预算超限 → 自动降级档位重规划（题面参考实例：预算 10，premium 估算 13 → 降级 standard 9.5 → 保存）；
3. 缺输入 → 不调用任何付费工具，明确说明缺什么；
4. 工具失败 → 重试/兜底/停止，始终保留已完成步骤的结果与花费；
5. 无可行方案 → 明确未完成状态 + 量化缺口（预算/工期缺口）；
6. 重复执行 → 已完成直接复用不重复扣费；未完成自动续跑（加分项）；
7. 步数上限 → 达到上限返回明确未完成状态；
8. 全部行为有可执行测试证明（16 个用例）与运行记录（examples/）。

## 实际用时与未完成部分

- 规划 + 实现 + 测试 + 文档：约 3 小时（AI 结对辅助，见 04-ai-usage.md）。
- 未完成部分：无（题面核心链路与全部验收点均已实现并有测试/示例覆盖）。多 Agent、HTTP API、部署按题面要求未做。
